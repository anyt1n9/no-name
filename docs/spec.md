# ソウルパス（仮）ゲーム仕様書

> 仮タイトル。公開前に、既存作品と名前が重複していないか確認する。

この文書は、これまでの相談で決まった内容をまとめたもの。数値（HP、攻撃力、確率など）はすべて仮で、実際に遊びながら調整する。

---

## 1. 概要

| 項目 | 内容 |
|---|---|
| ジャンル | ローグライク × タワーディフェンス |
| テーマ | ファンタジー（王国を魔王軍から守る） |
| 1回の冒険の長さ | 20〜30分 |
| 対応端末 | PCのみ（マウス操作） |
| 公開方法 | GitHub Pages（ブラウザで遊べる） |

### このゲームならではの特徴

1. **道そのものをプレイヤーが作る**：地形カードを置いて敵のルートを作り、その道に合わせて防衛する。「強いタワー × 良い地形」の組み合わせで勝つ。
2. **英雄の死が次の周回に残る**：英雄は何度でも蘇るが、死ぬたびに「魂の欠片」が残り、次の周回で墓や亡霊として現れる。過去の自分のプレイが、次の攻略材料や敵になる。
3. **敵側にもローグライク要素がある**：敵の特性は周回ごとに変わり、魔王はプレイヤーの戦い方を研究して対策してくる。

---

## 2. 世界観

- 魔王軍が王国に侵攻している。プレイヤーは王国を守る。
- 英雄は女神の加護により何度でも蘇る。ただし死ぬたびに「魂の欠片」が戦場に残る。
- 欠片は次の周回で「墓」や「亡霊」となって現れる。

---

## 3. 用語

| 用語 | 意味 |
|---|---|
| 冒険 | スタートからクリアまたは失敗までの1回のプレイ（1周） |
| 章 | 冒険を3つに分けた区切り。各章の最後にボスがいる |
| ステージ | 1回の防衛戦 |
| 準備フェーズ | ステージ開始前の、地形やタワーを配置する時間 |
| 戦闘フェーズ | 敵が攻めてくる時間 |
| 城HP | 守るべき城の体力。0になると冒険失敗。ステージ間で持ち越す |
| 王国 | 冒険の外にある拠点。施設を発展させて新要素を解放する |
| 魂の欠片 | 英雄が死ぬたびに残るもの。墓や亡霊の元になる |
| 遺品 | 墓や亡霊から手に入る、英雄ゆかりの強力なアイテム |
| 覚醒 | 欠片を英雄本人に返して強化すること |
| 脅威度 | 魔王がプレイヤーをどれだけ警戒しているかを表す数値 |
| 勢力 | 冒険で戦う魔王軍の派閥（ゴブリン王国など） |
| シード値 | ランダム要素を決める番号。同じ番号なら同じ展開を再現できる |

## 4. ゲームの流れ

```
【王国】施設の発展・英雄の雇用
   ↓
【出発準備】英雄を最大3人選ぶ → 戦う勢力を選ぶ
   ↓
【冒険】3章構成（各章 = ステージ4つ + 章ボス）
   各ステージ：準備フェーズ → 戦闘フェーズ → 報酬を3択で選ぶ
   第3章のボス = 選んだ勢力の王
   ↓
【結果】クリア または 城HPが0で失敗
   ↓
【冒険の記録画面】英雄の死亡記録や戦績を表示
   ↓
手に入れた資源を持って王国へ戻る
```

- 1ステージは1〜2分程度。全15戦で20〜30分を想定。
- 城HPは次のステージに持ち越す。
- ステージの合間で中断セーブできる。

---

## 5. ステージ（防衛戦）

### 5.1 準備フェーズ

- 地形カードのデッキからランダムに**5枚**を手札として引き、マップに配置する。
- タワーの設置と合体を行う。
- 敵の特性（今回のビルド）を確認できる（偵察）。

### 5.2 戦闘フェーズ

- 敵がウェーブ単位で、敵の城から味方の城に向かって進む。
- 敵を倒すとお金が手に入り、お金でタワーを追加設置できる。
- 英雄を**出撃させるタイミングはプレイヤーが決める**。移動先だけを指示し、戦闘は自動で行う。
- 戦闘中に地形を変えられるのはドルイドだけ。
- **一時停止**と**倍速**ができる。一時停止中も英雄への指示は出せる。

### 5.3 マップ

- マス目状のマップ。最初から置かれている地形はシード値で決まる。
- **敵の城（敵が出てくる場所）は左端の中央、味方の城は右端の中央に固定する。** 端や隅ではなく、広いマップの真ん中で戦えるようにするため。
- 毎回ちがう形の土地になるよう、次の地形を組み合わせてマップを作る。
  - **山脈**：マップを横切る山の列。1〜2か所のすき間が自然な関所になる
  - **湖**：通れず、タワーも建てられない水場
  - **森のかたまり**、**ぽつんと立つ岩山**
- 敵の城と味方の城のまわりは空けておく。
- マップの大きさは調整項目とする。

---

## 6. 地形システム（道づくり）

### 6.1 基本ルール

- 敵は「城に一番早く着ける道」を自動で選ぶ。地形による移動の遅さも考慮する。
- **敵のルートを変えられるのは地形カードだけ**。タワーは敵の通り道（ルート上）には建てられない。（v0.1 のテストプレイで「道を変えられるものが多すぎて持て余す」という感想があったため）
- **道を完全に塞ぐ配置はできない**。置こうとするとマスが赤く表示される。
- **飛行する敵は地形を無視する**。

### 6.2 地形の種類

| 地形 | 敵の通行 | 効果（案） |
|---|---|---|
| 山 | 通れない（壁） | 山の上に置いたタワーは射程が伸びる |
| 森 | 通れるが遅くなる | 弓とドルイドが強化される |
| 川 | 地上の敵は通れない | 水・雷属性のタワーが強化される |
| 橋 | 川の上に置くと渡れる | 敵が一列に並ぶので、範囲攻撃が当たりやすい |
| 洞窟 | 入口と出口の2マスで1組。敵は中を通り抜ける | 中にいる間は攻撃できない。道を長くも短くもできる |
| 崖 | 上から下への一方通行 | 敵に遠回りをさせられる |
| 湖 | 地上の敵は通れない | タワーも建てられない。カードにはならず、マップにだけ出てくる |

### 6.3 地形カード

- 報酬で集めてデッキにする。
- 毎ステージ、デッキからランダムに5枚を引く。

## 7. タワー

### 7.1 基本タワー

| タワー | 属性 | 役割（案） |
|---|---|---|
| 弓塔 | なし | 安い。飛行する敵も攻撃できる |
| 兵舎 | なし | 兵士を出し続け、道で敵を足止めする |
| 火の塔 | 火 | 範囲攻撃、燃焼 |
| 水の塔 | 水 | 敵を遅くする |
| 風の塔 | 風 | 攻撃が速い。飛行する敵も攻撃できる |
| 雷の塔 | 雷 | 敵から敵へ連鎖する攻撃 |
| 毒の塔 | 毒 | 時間をかけてダメージを与える |
| 光の塔 | 光 | 単体への高火力。アンデッドに強い |
| 闇の塔 | 闇 | 敵を弱体化させる（防御を下げる） |

- 属性は7つ：**火・水・風・雷・毒・光・闇**。
- 名前の分かりにくさを避けるため、「聖」は「光」に、「氷」は合体で生まれる効果（凍結）にまとめた。

### 7.2 合体

- **同じ属性の塔を2つ重ねる**と、その属性の上位版になる。
- **異なる属性の塔を重ねる**と、レシピ表にある組み合わせの場合だけ特殊な塔に進化する。
- **合体は1回まで**。合体した塔をさらに合体することはできない。
- 見つけたレシピは図鑑に記録される。

### 7.3 合体レシピ（初期案）

| 組み合わせ | 結果 |
|---|---|
| 火 + 風 | 爆炎の塔 |
| 水 + 雷 | 雷雨の塔 |
| 水 + 風 | 凍結の塔 |
| 毒 + 闇 | 呪毒の塔 |
| 火 + 闇 | 地獄の塔 |
| 光 + 光 | 神聖の塔（光の上位版） |

- 効果の詳細と、ほかのレシピは開発中に追加する。
- 属性は色だけでなくアイコンでも区別できるようにする。

## 8. 英雄

### 8.1 英雄は「個人」

- 各英雄は、名前・役職・レベル・装備・死亡記録を持つ。
- 同じ役職でも、一人ひとり別の個人として扱う。
- 王国の酒場で雇う。

### 8.2 役職

| 役職 | 戦い方 |
|---|---|
| 剣士 | 敵の前に移動して足止めする |
| 魔法使い | 敵が密集している地点へ移動して範囲魔法を撃つ |
| 弓兵 | 後方から攻撃する。飛行する敵も攻撃できる |
| 聖職者 | 味方を回復・強化する |
| ドルイド | 戦闘中にも地形を変えられる |
| ネクロマンサー | 倒した敵を兵士として使う |

- 職業名は上の6つで統一する（「戦士」「騎士」は「剣士」にまとめる）。

### 8.3 出撃のルール

- 冒険に出る前に、持っている英雄から**最大3人**を選ぶ。
- 戦場に**同時に出せるのは1人**。
- 出撃のタイミングはプレイヤーが決める。
- 英雄が倒れると**クールタイム**に入り、時間が経てば再び出撃できる。
- クールタイム中は、連れてきた**別の英雄に交代**して出撃できる。

---

## 9. 魂の欠片（英雄の死の記録）

### 9.1 死亡の記録

- 英雄は**倒れるたびに必ず**死亡として記録される（冒険に負けたときだけではない）。
- 記録する内容：誰が、どの冒険の、どのステージで、何に倒されたか。
- 記録はすべて残り、**図鑑**や**冒険の記録画面**で読める。

### 9.2 亡霊

- 亡霊は**英雄1人につき1体**。
- その英雄の死亡回数は**すべて**亡霊の強さに加算される。死んだ回数が多いほど亡霊は強くなる。
- 死亡記録のある英雄の亡霊は、次の周回で敵として出現する。
- 亡霊は、その英雄が死んだ時点の能力を引き継ぐ（過去の自分と戦う）。
- 亡霊を倒すと**遺品**が手に入る。
- 魔王の脅威度が高いほど、亡霊は早い章で現れ、さらに強くなる。
- 調整案：倒した亡霊の欠片は浄化され、強さへの加算がリセットされる（記録自体は残る）。

### 9.3 墓

- 1ステージに出る墓は**最大2つ**。
- 墓を調べると、**確率で**アイテム（遺品など）が出る。
- 墓では、欠片を英雄本人に返して**覚醒（強化）**させるイベントが起きることがある。
- 王国の教会を発展させるほど、墓が出やすくなる。

### 9.4 わざと死なせる作戦への対策

- クールタイム中は英雄が出せず、不利になる。
- 死ぬほど亡霊が強くなるので、死にはリスクがある。

## 10. 敵

### 10.1 勢力

冒険の開始時に、戦う勢力を選ぶ。

| 勢力 | 特徴 |
|---|---|
| ゴブリン王国 | 大量の雑魚、罠が多い、動きが速い |
| アンデッド帝国 | 倒しても復活する、HPが高い、毒・闇属性 |
| ドラゴン領 | 敵の数は少ないが1体ずつが非常に強い、飛行する敵が多い |

- 各勢力の第3章のボスは、その勢力の王。

### 10.2 敵のビルド

- 周回の開始時に、敵の特性がランダムに決まる。
  - 例：ゴブリン（HP 100）が、ある周回では「炎耐性」、別の周回では「死亡時に分裂」や「周囲の敵を高速化」を持つ。
- 特性は準備フェーズの偵察で確認できる。

### 10.3 魔王の脅威度

- 敵を倒すほど脅威度が上がる。
- 脅威度が上がると、次のウェーブに新しい敵、カウンター能力、ボス、特殊攻撃が追加される。
- **カウンター能力**：プレイヤーがよく使う属性への耐性を敵が持ち始める（魔王があなたを研究している）。
- **脅威度が高いほど報酬（資源）も増える**。脅威度を上げて稼ぐか、抑えて安全に進むかをプレイヤーが選べる。

### 10.4 飛行する敵

- 地形を無視して飛ぶ。
- 弓塔、風の塔、弓兵など、対空攻撃ができるものでしか攻撃できない。

---

## 11. 報酬

各ステージのクリア後に、3つの候補から1つを選ぶ。

- 新しいタワー
- 地形カード
- タワーの強化
- アイテム
- **祝福と呪い**：強い効果と引き換えにデメリットも付く。取るかどうかを悩ませる。

---

## 12. 王国の発展（周回をまたぐ成長）

冒険で手に入れた資源を使って施設を発展させ、新しい要素を解放する。

| 施設 | 解放するもの（案） |
|---|---|
| 酒場 | 新しい英雄（役職） |
| 鍛冶屋 | 装備、遺品の強化 |
| 魔法研究所 | 属性と合体 |
| 教会 | 墓の出やすさ、覚醒 |
| 市場 | アイテム、お金に関する効果 |

### 段階的な解放

遊ぶ人が少しずつ覚えられるよう、機能を順番に解放する。

- **最初の冒険**：基本タワー、英雄（剣士）、地形カード（山・森）
- **施設の発展で解放**：ほかの地形、属性と合体、勢力の選択、新しい役職 など

## 13. 快適さと記録の機能

- 一時停止と倍速
- 図鑑（敵、タワー、合体レシピ、英雄の死亡記録）
- 冒険の記録画面（例：「剣士アルフは第2章でゴブリン王に倒れた」）
- 中断セーブ（ステージの合間）
- セーブデータの書き出しと読み込み（ブラウザの保存データが消えたときのため）
- 色だけに頼らない表示（アイコンを併用する）
- **味方は青、敵は赤**で表示する（英雄・タワー・味方の城は青、魔物と敵の城は赤）。体力のバーも同じ色分けにする
- 敵の通る道は土の道として描き、進む向きを矢印で示す

## 14. 技術方針

| 項目 | 内容 |
|---|---|
| 言語 | TypeScript |
| ゲームライブラリ | Phaser（MITライセンス） |
| 開発ツール | Vite |
| 自動テスト | Vitest |
| 画面の確認 | Playwright（ヘッドレスブラウザ） |
| 公開 | GitHub Pages |

### 設計の原則

- **ルールと表示を分ける**：ゲームのルール部分は画面なしで動くように作る。自動テストや、自動で何度も遊ばせて難しさを測るシミュレーションができる。
- **中身はデータで管理する**：タワー、敵、英雄、地形、合体レシピ、報酬などは表（データ）で定義する。中身を増やすときにプログラムの書き換えを減らせる。
- **乱数はシード値で管理する**：同じシード値なら同じ展開を再現できる。
- **見た目は後から差し替える**：最初は丸や四角などの図形で作り、遊べることを優先する。

### フォルダ構成（案）

```
src/core/     ゲームのルール（画面に依存しない）
src/data/     タワー・敵・英雄・地形などのデータ
src/view/     Phaserによる画面表示
tests/        自動テスト
docs/         仕様書などの文書
public/       画像・音などの素材
```

## 16. 規約・ライセンス

- 画像や効果音は自作するか、CC0など再配布が許可された素材を使う。フォントはOFLなど利用条件が明確なものを使う。
- 既存ゲームのタイトル、キャラクター、画像、特徴的なデザインはまねしない。ジャンルとして一般的な仕組みや、一般的な魔物（スライム、ゴブリンなど）を出すのは問題ない。
- Phaserなどのライブラリのライセンス表示を残す。
- 使用した素材のクレジットをゲーム内に表示する。
- リポジトリは公開されているので、APIキーなどの秘密情報は入れない。
- 公開前に、ゲーム名が既存作品と重複していないか確認する。
